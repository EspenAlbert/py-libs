    Contributing to pkg-ext

    Guidelines for developing with and contributing to pkg-ext.

    Quick Start

    # Install in project
uv pip install pkg-ext

# Or run via uvx
uvx pkg-ext --help

    Developer Workflow

    Daily Development Cycle

    # 1. Make code changes (add/remove symbols)
# 2. Handle new/removed symbols interactively
pkg-ext pre-change

# 3. Fill in examples in {group}_examples.py
# 4. Run tests locally
pytest

# 5. Validate and update dev files (CI mode)
pkg-ext pre-commit

# 6. Commit and push
git add -A && git commit -m "feat: add new feature"
git push

    After PR Merge

    CI runs automatically, or manually:

    # On main branch after merge
pkg-ext post-merge --push --pr 123

    Workflow Commands

    Command When Mode Writes
    pre-change After adding/removing symbols Interactive {group}_examples.py, {group}_test.py
    pre-commit Before commit / CI validation Bot -dev files, docs, API diff
    post-merge After merge to main Bot Real files, VERSION bump, git tag
    chore Internal changes needing release Bot .changelog/{pr}.yaml
    diff-api Manual API comparison Bot Nothing (output only)

    Command Details

    pre-change - Interactive symbol handling: 

    pkg-ext pre-change           # All groups
pkg-ext pre-change -g config # Single group
    - Prompts for new symbols: make_public or keep_private - Prompts for removed symbols: delete or rename - Generates example and test scaffolds

    pre-commit - CI validation mode: 

    pkg-ext pre-commit              # With docs regeneration
pkg-ext pre-commit --skip-docs  # Faster iteration
    - Fails if pending prompts (undecided symbols) - Updates -dev suffix files (not production files) - Regenerates documentation

    post-merge - Release mode: 

    pkg-ext post-merge --push --pr 123
pkg-ext post-merge --pr 123 --force-reason "CI improvements"
    - Bumps VERSION based on changelog actions - Creates git tag - Copies dev files to production files - Archives old changelog entries - Skips release when no changelog entries (use --force-reason to override)

    chore - Internal changes: 

    pkg-ext chore -d "CI improvements"
pkg-ext chore -d "Dependency updates" --pr 4
    - Creates a ChoreAction in .changelog/{pr}.yaml - Triggers a patch version bump - Use for internal changes (refactoring, CI, dependencies) that warrant a release

    Stability Management

    Stability levels are managed through CLI commands, not by manually adding decorators. pkg-ext tracks stability in .changelog/ and generates the appropriate wrapper code in group modules.

    Stability Levels

    Level Description
    experimental New feature, may change
    ga Generally available, stable API
    deprecated Will be removed, use replacement

    Stability Targets

    Commands support three target levels:

    Target Format Example
    Group {group} config
    Symbol {group}.{symbol} config.parse
    Argument {group}.{symbol}.{arg} config.parse.timeout

    CLI Commands

    # Mark group as experimental
pkg-ext exp --target config

# Mark symbol as experimental
pkg-ext exp --target config.parse

# Mark argument as experimental
pkg-ext exp --target config.parse.timeout

# Graduate to GA (stable)
pkg-ext ga --target config

# Mark as deprecated with replacement
pkg-ext dep --target config --replacement new_config

    How It Works

    1. Run pkg-ext exp --target my_group to mark a group as experimental
    2. pkg-ext creates a changelog entry in .changelog/
    3. On pre-commit, pkg-ext generates {group}.py with stability wrappers
    4. Consumers see warnings when calling experimental/deprecated symbols

    Suppressing Warnings (for package consumers)

    Package consumers can suppress stability warnings:

    import warnings
from my_pkg._warnings import MyPkgExperimentalWarning

warnings.filterwarnings("ignore", category=MyPkgExperimentalWarning)

    In pytest (pyproject.toml):

    [tool.pytest.ini_options]
filterwarnings = [
    "ignore::my_pkg._warnings.MyPkgExperimentalWarning",
]

    Configuration

    Project Config (pyproject.toml)

    [tool.pkg-ext]
tag_prefix = "v"
file_header = "# Generated by pkg-ext"
commit_fix_prefixes = ["fix:", "bugfix:", "hotfix:"]
format_command = ["ruff", "format"]  # ruff check --fix always runs first

[tool.pkg-ext.groups.my_group]
dependencies = ["__ROOT__"]
docs_exclude = ["internal_helper"]
docstring = "Utilities for common operations"

    User Config (~/.config/pkg-ext/config.toml)

    [user]
editor = "cursor"
skip_open_in_editor = false

    Section Markers

    pkg-ext uses section markers to preserve user content during regeneration.

    Marker Format

    # === DO_NOT_EDIT: pkg-ext {id} ===
# Generated content here
# === OK_EDIT ===
# User content preserved here

    Common Marker IDs

    File Marker IDs
    {group}_examples.py {symbol}-example-{name}
    {group}_test.py {symbol}-test
    docs/{group}/{symbol}.md {symbol}-def, {symbol}-changes

    Generated Files

    Dev Mode Files (PR development)

    File Purpose
    .groups-dev.yaml Group assignments (dev copy)
    CHANGELOG-dev.md Human-readable changelog (dev copy)
    .changelog/{pr}.yaml Changelog actions for this PR
    {pkg}/_warnings.py Stability warning decorators
    {pkg}.api-dev.yaml API dump for comparison (gitignored)
    {group}_examples.py Example scaffolds
    {group}_test.py Test scaffolds

    Production Files (after merge)

    File What Changes
    .groups.yaml Copied from dev
    CHANGELOG.md Copied from dev
    {pkg}/__init__.py VERSION updated
    {pkg}.api.yaml API baseline dump
    pyproject.toml Version field updated

    Common Issues

    "Pending decisions" error in CI

    Cause: New symbols haven't been decided (make_public or keep_private)

    Fix: Run pkg-ext pre-change locally and answer prompts

    Generated files not staged

    Cause: pre-commit checks for unstaged generated files

    Fix: Run git add on generated files before committing

    Symbol not appearing in docs

    Cause: Symbol may be in docs_exclude or not yet exposed

    Fix: Check pyproject.toml groups config and .groups.yaml

    Known Limitations

    • Removed reference handling: select_ref and select_multiple_ref_state raise NotImplementedError
    • Alias creation: confirm_create_alias always returns False
    • Non-callable symbols: Constants and type aliases don't emit stability warnings
    • Arg-level stability: Only available for GA groups
